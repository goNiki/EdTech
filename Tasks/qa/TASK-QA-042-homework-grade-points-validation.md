# 🧪 [QA-042] Тестирование валидации диапазона баллов при проверке домашних заданий

> **Объект тестирования:** Эндпоинт ручной оценки попыток `POST /api/v1/quizzes/attempts/{attempt_id}/answers/{answer_id}/grade`  
> **Связанные задачи разработки:** [TASK-BE-038](../backend/TASK-BE-038-homework-grade-points-validation.md), [TASK-FE-042](../frontend/TASK-FE-042-modal-grade-hw-input-validation.md)  
> **Спецификация фичи:** [internal/service/quiz/FUNCTIONAL_SPEC.md](../../internal/service/quiz/FUNCTIONAL_SPEC.md)

---

## 🎯 Цель тестирования
Проверить исправление дефекта валидации баллов: убедиться, что система строго отклоняет отрицательные значения баллов (`points < 0`) и баллы, превышающие максимальный балл задания/квиза (`points > maxPoints`), возвращая `400 Bad Request` и не допуская сохранения некорректных данных в БД.

---

## 🧪 Тест-кейсы (Test Matrix)

### 1. Позитивные сценарии (Happy Path)
1. **Кейс 1.1 (Выставление нулевого балла):** Преподаватель оценивает ответ студента с `points = 0` и комментарием `feedback = "Неверно"`. Ожидание: HTTP 200 OK, в `quiz_attempt_answers` сохраняются `points = 0`, `is_correct = false`.
2. **Кейс 1.2 (Выставление максимального балла):** Преподаватель выставляет `points = maxPoints` (например, 25). Ожидание: HTTP 200 OK, `points = 25`, `is_correct = true`.
3. **Кейс 1.3 (Промежуточный корректный балл):** Преподаватель выставляет `points = 15` (при `maxPoints = 25`). Ожидание: HTTP 200 OK.

### 2. Негативные сценарии и валидация (Negative Path)
1. **Кейс 2.1 (Отрицательный балл):** Отправка `{"points": -5, "feedback": "Negative"}`. Ожидание: HTTP 400 Bad Request, ошибка валидации.
2. **Кейс 2.2 (Балл выше максимального):** Отправка `{"points": 999, "feedback": "Over max"}`. Ожидание: HTTP 400 Bad Request с кодом ошибки `INVALID_GRADE_POINTS` и сообщением «Балл не может быть меньше 0 или превышать максимальный балл задания».
3. **Кейс 2.3 (Превышение на 1 балл):** При `maxPoints = 25` отправка `{"points": 26}`. Ожидание: HTTP 400 Bad Request.

### 3. Проверка целостности данных в базе (Database Integrity)
1. **Кейс 3.1 (Откат транзакции при ошибке):** Убедиться, что при получении 400 Bad Request запись в таблице `quiz_attempt_answers` остаётся без изменений (`points` не перезаписывается некорректным значением, `is_correct` остаётся `NULL` или прежним).
2. **Кейс 3.2 (Уведомления):** Проверить, что студенту НЕ отправляется in-app уведомление при отклонении запроса валидацией.
