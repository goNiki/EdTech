> **Документация модуля:** [internal/service/progress/README.md](../../internal/service/README.md)

## 🎯 Цель задачи
Устранить критическую уязвимость в логике завершения уроков.
В текущей реализации при вызове `POST /api/v1/lessons/{id}/complete` клиент может передать произвольный `score` (или опустить его, из-за чего клиентский код подставляет дефолтные `100` баллов), и бэкенд безусловно фиксирует `score = 100` и помечает урок как пройденный (`status = 'completed'`). Это позволяет студенту открыть любой сложный контрольный тест, нажать кнопку в шапке и мгновенно получить максимальный балл, не решив ни одного задания.

В рамках задачи необходимо:
1. Запретить безусловную установку `100` баллов на сервере для уроков, содержащих проверочные тесты.
2. Реализовать серверный пересчет баллов на основе проверенных попыток (`quiz_attempts`), либо строгую валидацию переданных ответов.
3. Обеспечить корректную фиксацию досрочного завершения тестирования (с сохранением реального балла за отвеченные вопросы и `0` за пропущенные).

---

## 🔍 Текущее состояние кода
- В `internal/interfaces/handlers/progress/complete.go`:
  Хендлер принимает `dto.CompleteLessonRequest{ Score: req.Score }` и напрямую передает его в сервис.
- В `internal/service/progress/completeLesson.go`:
  Сервис обновляет запись в таблице `lesson_progress`, записывая полученный от клиента `score` без сверки с реальными блоками тестов в `lesson.content` и без проверки существующих записей в таблице `quiz_attempts`.

## 📝 Технические требования к реализации

### 1. API / Handlers (`internal/interfaces/handlers/progress/`)
- Эндпоинт `POST /api/v1/lessons/{id}/complete`:
  - **Request Body (`dto.CompleteLessonRequest`):**
    ```json
    {
      "attempt_id": 15,
      "answers": [
        { "block_id": "QuizSingleBlock-123", "answer": 1 }
      ],
      "is_abandoned": false
    }
    ```
  - Если урок содержит интерактивные тесты (`lesson.type IN ('test', 'quiz')` или в `lesson.content` присутствуют блоки `Quiz...`):
    - Поле `score`, переданное клиентом напрямую, **игнорируется** или валидируется.
    - Сервер рассчитывает балл самостоятельно на основе ответов или считывает верифицированный результат связанной попытки `quiz_attempt_id`.
    - Если студент завершает тест досрочно (`is_abandoned: true`), неотвеченные вопросы оцениваются в 0 баллов, попытка закрывается, а в прогресс записывается фактически набранный процент.

### 2. Бизнес-логика (Service Layer `internal/service/progress/`)
- В методе `CompleteLesson`:
  1. Загрузить урок `lesson, err := s.lessonRepo.GetByID(ctx, lessonID)`.
  2. Проверить, содержит ли урок тесты.
  3. Для уроков-лекций без тестов (`lecture` без квизов): разрешить установку `score = 100` (факт прочтения материала).
  4. Для уроков с тестами:
     - Если передан `attempt_id`: проверить, что попытка принадлежит данному пользователю и уроку, рассчитать суммарный процент правильных ответов `verifiedScore = (earnedPoints / totalPoints) * 100`.
     - Записать в таблицу `lesson_progress` вычисленный `verifiedScore`.
  5. Вернуть клиенту DTO с детальной информацией:
     ```json
     {
       "lesson_id": 10,
       "status": "completed",
       "score": 45,
       "earned_points": 9,
       "total_points": 20,
       "is_passed": false
     }
     ```

## ✅ Критерии приёмки (Definition of Done)
- [x] Прямой вызов `POST /lessons/{id}/complete` с пустым телом или `{ score: 100 }` для урока с тестами больше не начисляет 100 баллов.
- [x] Сервер вычисляет итоговый балл строго на основе правильности ответов студента.
- [x] При досрочном завершении теста фиксируется фактический балл за решенные задачи (пропущенные = 0).
- [x] Обычные лекции без тестовых блоков по-прежнему завершаются со 100% прогрессом.
