## 1. Описание проблемы (Problem Statement)
1. **Баг парсера быстрых тестов (`quiz-parser.ts`):**
   - При импорте тестов из шаблона Aiken или с нумерацией (например, `1. Какой паттерн обеспечивает чистую изоляцию...`) парсер ошибочно распознавал первую строку с нумерацией `1.` как первый вариант ответа.
   - В результате формулировка вопроса оставалась пустой (подставлялось имя по умолчанию «Вопрос 1»), а сам текст вопроса добавлялся как лишний вариант ответа.
   - Если вручную убрать цифру `1.`, строка распознавалась как вопрос.
2. **Баг добавления блоков документа (.docx/.md) и квизов на холст Puck:**
   - При нажатии кнопок в шапке редактора («Вставить документ .docx / .md» и «Быстрый импорт тестов -> Добавить в урок») всплывало успешное уведомление, но на холсте Puck новые блоки не появлялись.
   - Причина: компонент `<Puck>` в `@puckeditor/core` инициализирует внутренний стейт через `useState(() => initialData)` и игнорирует обновления пропа `data` без смены ключа монтирования `key={editorKey}`.

---

## 2. Анализ причин и план решения
1. **В `frontend/src/lib/quiz-parser.ts`:**
   - Исправлено регулярное выражение распознавания вариантов ответов.
   - Первая строка блока вопроса (до обнаружения вариантов A., B., C., D. или чекбоксов `[ ]`) гарантированно трактуется как текст вопроса (`questionLines`), даже если она начинается с `1. `, `1) `, `Вопрос 1:`, `# 1.` и т.п.
   - Буквенные варианты ответов отделены от числовой нумерации вопросов.
2. **В `frontend/src/app/teacher/lessons/[id]/edit/page.tsx`:**
   - Добавлено сохранение актуального состояния холста через `onChange={(data) => { currentPuckDataRef.current = data; }}`.
   - При вставке документа или быстром импорте тестов берется текущий контент из `currentPuckDataRef.current || initialData`, добавляются новые блоки в массив `content` и инкрементируется `editorKey` (`setEditorKey(k => k + 1)`) для немедленного перерендера холста Puck с новыми блоками.
