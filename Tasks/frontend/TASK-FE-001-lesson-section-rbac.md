# 🎨 [FE-001] Обработка прав доступа и ошибок 403 Forbidden в конструкторе курсов

**Статус:** ✅ Completed

> **Приоритет:** Critical (P0)  
> **Связанные задачи:** BE-001, QA-001  
> **Компоненты / Страницы:** `frontend/src/app/teacher/courses/[id]/curriculum/page.tsx`, `frontend/src/app/teacher/lessons/[id]/edit/page.tsx`, `frontend/src/components/teacher/`

## 🎯 Цель задачи
Обеспечить корректную реакцию пользовательского интерфейса на проверки прав доступа бэкенда: блокировать попытки редактирования чужих курсов, отображать понятные уведомления об отсутствии прав и предотвращать потерю несохраненных данных при ошибке 403.

## 🖥 Пользовательский интерфейс (UI / UX)
- **Экран силлабуса (`/teacher/courses/[id]/curriculum`):**
  - При получении `403 Forbidden` на операции создания, редактирования, удаления или реордеринга модулей и уроков выводить модальное окно/тост: *«У вас нет прав на редактирование этого курса. Изменения не сохранены.»*
  - Если в данных курса `permissions.can_edit === false`, скрывать кнопки добавления («+ Добавить модуль», «+ Новый урок») и переводить силлабус в режим «Только чтение».
- **Визуальный редактор Puck (`/teacher/lessons/[id]/edit`):**
  - При попытке сохранения урока (`PATCH /lessons/{id}`), возвращающей статус 403, выводить алерт с предупреждением и запрещать дальнейшее автосохранение.
  - Добавить бейдж «Режим просмотра (Только чтение)» в хедере редактора, если у пользователя нет прав автора.

## 🔌 Интеграция с API (Контракт с Бэкендом)
- **Вызовы:**
  - `POST /api/v1/sections`, `PATCH /api/v1/sections/{id}`, `DELETE /api/v1/sections/{id}`
  - `POST /api/v1/lessons`, `PATCH /api/v1/lessons/{id}`, `DELETE /api/v1/lessons/{id}`
  - `PUT /api/v1/courses/{id}/reorder-sections`, `PUT /api/v1/sections/{id}/reorder-lessons`
- **Обработка ответа 403:**
  - Перехватывать в блоках `catch (err: any)` статус `err.response?.status === 403`.
  - Не затирать локальный стейт и форму при ошибке, давая пользователю возможность скопировать введенный текст.

## ✅ Критерии приёмки (Definition of Done)
- [x] Пользователь без роли автора/преподавателя не может случайно сломать контент через интерфейс.
- [x] Ошибка 403 сопровождается читаемым русскоязычным сообщением вместо абстрактной ошибки сети.
- [x] При отсутствии прав на редактирование интерфейс переключается в состояние View-Only.
