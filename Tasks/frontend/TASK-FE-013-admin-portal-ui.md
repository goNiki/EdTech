# 🎨 [FE-013] Панель администратора: реестр пользователей, назначение ролей и бан

> **Приоритет:** Low (P2)  
> **Связанные задачи:** BE-013, QA-013  
> **Компоненты / Страницы:** `frontend/src/app/admin/users/page.tsx`, `frontend/src/components/layout/Sidebar.tsx`

## 🎯 Цель задачи
Разработать интерфейс панели управления администратора (`/admin/users`). Сейчас новый зарегистрированный пользователь не может стать преподавателем без вмешательства в базу данных через консоль. Административная панель позволит централизованно управлять учетными записями, назначать роли преподавателя и блокировать нарушителей.

## 🖥 Пользовательский интерфейс (UI / UX)
- **Доступ и навигация:**
  - В `Sidebar.tsx` для пользователей с `user.role === 'admin'` выводить пункт навигации:  
    `[ Иконка Shield ] Панель администратора (/admin/users)`.
  - Защита маршрута: `ProtectedRoute allowedRoles={['admin']}`.
- **Экран `/admin/users`:**
  - Шапка: статистика (всего пользователей, активных, преподавателей, заблокированных).
  - Панель фильтров: поиск по email/имени, фильтр по роли, тумблер «Только заблокированные».
  - Таблица пользователей:
    - Аватар, имя, email, никнейм.
    - Селект роли: выпадающий список (`Студент`, `Преподаватель`, `Автор`, `Администратор`) с мгновенным изменением по клику с подтверждением.
    - Статус: зеленый «Активен» / красный «Заблокирован».
    - Кнопка действия: «Заблокировать» / «Разблокировать».

## 🔌 Интеграция с API (Контракт с Бэкендом)
- Загрузка пользователей: `GET /api/v1/admin/users`
- Смена роли:
  ```typescript
  await api.patch(`/admin/users/${userId}/role`, { role: newRole });
  ```
- Блокировка:
  ```typescript
  await api.patch(`/admin/users/${userId}/ban`, { is_banned: targetStatus });
  ```

## ✅ Критерии приёмки (Definition of Done)
- [x] Администратор может перевести студента в роль преподавателя в 1 клик.
- [x] Обычные студенты и преподаватели не имеют доступа к экрану `/admin/users` (403).
- [x] Блокировка пользователя моментально обновляет статус в интерфейсе.
