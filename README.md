# 🎓 EdTech Platform (LMS)

> Высоконагруженная образовательная платформа (LMS) уровня Stepik / Coursera для создания курсов, интерактивного обучения, тестирования и аналитики успеваемости. Проект спроектирован с упором на надежность, расширяемость и строгие инженерные практики: **Clean Architecture** и **Domain-Driven Design (DDD)**.

---

## ⚡ Технологический стек

### Backend
- **Язык:** Go (Golang 1.27)
- **Роутер & Middleware:** `go-chi/chi/v5`, `go-chi/render`
- **База данных:** PostgreSQL 15, драйвер `jackc/pgx/v5` (connection pooling, binary protocol)
- **Транзакции:** `TxManager` с поддержкой уровней изоляции (`pgx.TxOptions`)
- **Миграции:** `pressly/goose/v3` (версионированные SQL-миграции с транзакционным накатом)
- **Аутентификация & RBAC:** JWT (Access + Refresh токены), bcrypt-хеширование, матрица прав доступа (`RolePermissions`)
- **Валидация & Конфигурация:** `go-playground/validator/v10`, `caarlos0/env/v11`
- **Логирование:** Структурированный логгер `log/slog`

### Frontend (В разработке)
- **Фреймворк:** Next.js 15 (App Router, React 19, TypeScript)
- **Стилизация:** Tailwind CSS
- **UI-компоненты:** `shadcn/ui` (Radix UI)
- **Конструктор уроков:** `Puck` (архитектура Content-as-Data для блочного интерактивного редактирования контента)

### DevOps & Инфраструктура
- **Контейнеризация:** Docker, Docker Compose (multi-stage сборка образов на базе `alpine`)
- **Оркестрация запуска:** Автоматический контейнер-мигратор (`edtech-migrator`), гарантирующий накат схемы БД перед стартом API-сервера

## 🏛 Архитектура проекта (Clean Architecture & DDD)

Каждый бизнес-модуль платформы строго разделен на независимые слои (принцип инверсии зависимостей, Dependency Inversion):

```
internal/
├── domain/                      # Rich Domain: сущности + бизнес-правила (без тегов БД и JSON)
├── service/                     # Оркестрация сценариев (1 use-case = 1 файл, без сырого SQL и логов)
├── repository/                  # Интерфейсы репозиториев (db.QueryExecutor)
├── repository/models/           # Изолированные сущности базы данных (ORM/Scan-модели)
├── repository/models/converter/ # Конвертеры: models (DB) ↔ domain (Бизнес)
├── interfaces/handlers/         # HTTP-контроллеры (валидация, единый рендеринг, логирование ошибок)
├── interfaces/handlers/converter/# Конвертеры: domain (Бизнес) ↔ dto (HTTP)
├── dto/                         # Контракты запросов/ответов (Request/Response DTO)
├── interfaces/middleware/       # JWT Auth, Optional JWT, RequestID, Recovery, Logger, CORS
└── infrastructure/              # Драйвер БД, TxManager, Hashers, JWT, Logger, Config
```

### Ключевые архитектурные гарантии:
1. **Rich Domain Models:** Доменные модели (`Course`, `Section`, `Lesson`, `Quiz`, `Progress`) инкапсулируют бизнес-правила по паттерну *Guard + Mutate* (`CanPublish()` -> `Publish()`).
2. **Чистый сервисный слой:** Сервисы **никогда** не пишут SQL-запросы, не импортируют драйверы БД и не вызывают логгер. Все ошибки трассируются через `const op = "service.<module>.<Method>"` с сохранением цепочки через `%w`.
3. **Безопасные транзакции:** Любые составные мутации (зачисление студента с инкрементом счетчика, каскадная смена статусов, сохранение прогресса с эссе) выполняются через `txManager.WithTX(ctx, pgx.TxOptions{}, func(ctx, tx) error { ... })`.
4. **Изоляция данных:** Хендлеры никогда не отдают доменные структуры напрямую клиенту — маппинг в DTO выполняется строго через изолированный слой конвертеров.

## 🧩 Функциональные возможности

### 1. Пользователи и Авторизация (`/auth`, `/admin`)
- Регистрация студентов (защита от несанкционированной эскалации роли).
- Аутентификация с выдачей пары JWT: короткоживущий `access_token` и `refresh_token` с хранением в БД.
- Ролевая модель (RBAC): `student`, `teacher`, `admin`.
- Профиль пользователя, смена пароля, верификация email, блокировка/бан пользователей администратором.

### 2. Курсы и Каталог (`/courses`)
- Создание и управление курсами (название, slug, описание, обложка, сложность, теги, категория, цена).
- Жизненный цикл курса: черновик (`draft`), опубликован (`published`), в архиве (`archived`).
- Публичный каталог с гибкой пагинацией и фильтрами.
- Презентационный режим (лендинг курса для гостей) и полный режим структуры (для зачисленных учеников).
- Переупорядочивание модулей (`reorder-sections`).

### 3. Секции и Уроки (`/sections`, `/lessons`)
- Иерархия контента: **Курс → Секции (Модули) → Уроки**.
- Типы уроков: видео, теория (лонгриды), интерактивные блоки, практические задания.
- Drag-and-drop сортировка уроков внутри секций (`reorder-lessons`).
- Бесплатные ознакомительные превью-уроки (`is_free = true`) для привлечения аудитории.
- Каскадное управление статусами публикации модулей и уроков.

### 4. Тестирование и Проверка заданий (`/quizzes`)
- Автоматические тесты: выбор одного правильного ответа (`single_choice`), мульти-выбор (`multiple_choice`).
- Ограничение по времени (`time_limit`) и лимит попыток (`max_attempts`).
- Задания с развернутым ответом (эссе / домашние работы) с возможностью прикрепления вложений.
- Кабинет проверки преподавателя (`/grading/pending`): ручная оценка, выставление баллов и развернутый текстовый фидбек ученику.
- Пессимистическая блокировка попыток через PostgreSQL Advisory Locks для предотвращения Race Conditions при параллельной отправке ответов.

### 5. Зачисление на курсы (`/enrollment`)
- Самостоятельная запись студентов (`self-enroll`) на открытые опубликованные курсы.
- Ручное приглашение и зачисление студентов преподавателем (`teacher-enroll`) по ID или Email.
- Отчисление с курса и изменение ролей участников внутри курса (студент, ассистент, преподаватель).

### 6. Прогресс обучения (`/progress`)
- Автоматический трекинг прогресса каждого урока (`in_progress`, `completed`).
- Учет времени просмотра видео (`watch_time`) и сохранение последней позиции таймлайна (`last_position`).
- Автоматический расчет общего процента прохождения курса и среднего балла на уровне базы данных и транзакций.

### 7. Аналитика преподавателя (`/analytics`)
- Сводный дашборд успеваемости курса: общее количество студентов, процент завершения, средний балл.
- Детальный срез по конкретному студенту (`drilldown`): история прохождения уроков, результаты тестов, время на платформе.

## 🚀 Быстрый запуск

### Вариант 1: Полный запуск через Docker Compose (Рекомендуется)

Проект полностью упакован в Docker. Все миграции накатятся автоматически перед стартом бэкенда:

```bash
# 1. Клонируйте репозиторий
git clone https://github.com/your-username/EdTech.git
cd EdTech

# 2. Создайте файл окружения (или отредактируйте .env)
cp .env .env.local

# 3. Запустите стек сервисов в фоне
docker-compose up --build -d
```

Сервисы будут доступны по следующим адресам:
- **Бэкенд API:** `http://localhost:8082`
- **PostgreSQL:** `localhost:5433` (внутри контейнера порт 5432)

Просмотр логов приложения в реальном времени:
```bash
docker-compose logs -f app
```

Остановка контейнеров:
```bash
docker-compose down
```

---

### Вариант 2: Локальная сборка и запуск (Go)

Требования: установленный **Go 1.25+** и запущенный **PostgreSQL 15+**.

1. **Установите зависимости:**
   ```bash
   go mod download
   ```

2. **Настройте переменные окружения в `.env`:**
   ```env
   SERVER_HOST=localhost
   SERVER_PORT=8082
   DB_HOST=localhost
   DB_PORT=5432
   DB_USER=postgres
   DB_PASSWORD=postgres
   DB_NAME=edtech
   JWT_SECRET=super_secret_jwt_key_123
   ```

3. **Примените миграции базы данных:**
   ```bash
   go run ./cmd/migration/migration.go up
   ```
   *(Или запустите утилиту без аргументов для входа в интерактивный CLI-режим мигратора).*

4. **Запустите сервер:**
   ```bash
   go run ./cmd/edtech/main.go
   ```

5. **Прогоните тесты и линтеры:**
   ```bash
   go test ./internal/...
   go vet ./...
   ```

## 📜 База данных и миграции

Все миграции схемы расположены в каталоге [`migrators/`](./migrators) и версионируются через `goose`:
- Таблицы пользователей, сессий JWT и прав доступа (`users`, `refresh_tokens`, `permissions`, `role_permissions`).
- Каталог курсов, категорий, секций, уроков и внешних ресурсов (`courses`, `categories`, `sections`, `lessons`, `resources`).
- Учет зачисления на курсы (`users_courses`).
- Система прогресса обучения (`lesson_progress`, `course_progress`) с автоматическими триггерами пересчета.
- Система квизов, вопросов, попыток и ответов (`quizzes`, `quiz_questions`, `quiz_answers`, `quiz_attempts`, `quiz_attempt_answers`).
