## 🏛 Золотые стандарты и паттерны фронтенда

### 1. Архитектура и разделение слоёв (Clean Frontend)
* **Разделение ответственностей (SoC):** 
  Никакой бизнес-логики и прямых сетевых вызовов внутри JSX/шаблонов.
  - `UI (Presentational)`: Чистые компоненты без побочных эффектов. Принимают `props`, рендерят разметку.
  - `Hooks / Logic (Container)`: Кастомные хуки инкапсулируют локальное состояние, эффекты и вызовы API.
  - `API Layer`: Типизированные клиенты, схемы валидации (Zod/Valibot).
* **Композиция вместо проп-дриллинга:** Использование `children`, Compound Components (паттерн составных компонентов) и Headless-подходов вместо гигантских компонентов с 40 пропсами.

### 2. Управление состоянием (State Segregation)
Строго разделяй типы состояния — не смешивай их:
* **Server State:** Только через инструменты кэширования (TanStack Query / SWR / RTK Query). Никаких `useEffect` для ручного фетчинга данных.
* **Global Client State:** Минималистичные сторы (Zustand, Pinia, Redux Toolkit) только для реально глобальных вещей (тема, пользовательская сессия, корзина).
* **URL State:** Фильтры, сортировки, пагинация и вкладки должны жить в Query-параметрах URL, чтобы ссылкой можно было поделиться.
* **Local UI State:** `useState` / `useReducer` только для локального визуала (открыта ли модалка/дропдаун).

### 3. Обязательные состояния интерфейса (The 4 UI States)
Каждый компонент, работающий с данными, **обязан** корректно обрабатывать 4 состояния:
1. `Loading / Pending`: Скелетоны (Skeletons) вместо блокирующих спиннеров на весь экран.
2. `Empty`: Понятный экран с подсказкой и действием («Нет заказов. Нажмите, чтобы создать»).
3. `Error`: Локальный Error Boundary, понятное сообщение об ошибке и кнопка «Повторить попытку».
4. `Success`: Отображение целевых данных.

### 4. Производительность и доступность (Performance & A11y)
* Оптимизация ре-рендеров: избегать лишних аллокаций функций и объектов в props без необходимости.
* Ленивая загрузка (`lazy / Suspense`) для тяжёлых модалок, чартов и вторичных страниц.
* Доступность: правильная семантика HTML5 (`<main>`, `<nav>`, `<button>` вместо `<div onClick>`), поддержка фокуса с клавиатуры и `aria-*` атрибуты.

## 🌐 Браузерное и визуальное тестирование (MCP Puppeteer)

Для полноценной проверки пользовательского интерфейса, форм, интерактивных редакторов и стилей разработчик напрямую взаимодействует с браузером через инструменты **MCP Puppeteer**:
* `puppeteer_navigate`: открытие страниц приложения (`http://localhost:3000/...`).
* `puppeteer_fill`: заполнение текстовых инпутов, полей форм и логина.
* `puppeteer_click`: эмуляция кликов по кнопкам, вкладкам, чекбоксам и тулбарам.
* `puppeteer_screenshot`: снятие скриншотов целевых страниц или компонентов (`width: 1280, height: 800`) для визуального контроля вёрстки и подтверждения отсутствия багов.
* `puppeteer_evaluate`: выполнение проверочных скриптов в консоли браузера (проверка LocalStorage, токенов, DOM-узлов).
