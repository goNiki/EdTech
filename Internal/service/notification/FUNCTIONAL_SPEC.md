# Функциональная спецификация: In-App Notification Center (`internal/service/notification`)

## 1. Общее описание
Система пользовательских уведомлений предназначена для информирования студентов и преподавателей о ключевых событиях на образовательной платформе:
1. Проверка практических заданий и эссе преподавателем (`homework_graded`).
2. Сдача студентом новой работы на проверку (`new_submission`).
3. Публикация нового материала в курсе (`new_lesson`).

---

## 2. Паспорта функций

### 2.1. Создание уведомления (`CreateNotification`)
* **Входные параметры:**
  * `userID` (`int64`, обязательный) — идентификатор получателя.
  * `title` (`string`, обязательный) — заголовок уведомления.
  * `message` (`string`, обязательный) — текст уведомления.
  * `nType` (`domain.NotificationType`, обязательный) — тип события (`homework_graded`, `new_submission`, `new_lesson`).
  * `linkURL` (`*string`, опциональный) — относительный URL для перехода (например, `/lessons/42`).
* **Пошаговый алгоритм:**
  1. Валидация: `userID > 0`, `title != ""`, `message != ""`. При ошибке возвращается `ErrValidationFailed`.
  2. Формирование структуры `domain.Notification` со статусом `IsRead = false`.
  3. Сохранение записи в БД через `NotificationRepository.CreateNotification`.
  4. Возврат созданного объекта с присвоенным `id` и `created_at`.
* **Сайд-эффекты:** Добавление строки в таблицу `notifications`.
* **Ошибки:** `ErrValidationFailed`, `ErrInternalDB`.

---

### 2.2. Получение ленты уведомлений (`GetFeed`)
* **Входные параметры:**
  * `userID` (`int64`, обязательный) — текущий пользователь.
  * `limit` (`int`, опциональный, по умолчанию 20, максимум 100) — количество запрашиваемых записей.
* **Пошаговый алгоритм:**
  1. Проверка `userID > 0`.
  2. Нормализация лимита (если `<= 0`, устанавливается 20).
  3. Выборка последних записей пользователя, отсортированных по дате создания убывающе (`created_at DESC`).
  4. Подсчет общего количества непрочитанных уведомлений пользователя (`is_read = FALSE`) с использованием частичного индекса.
  5. Формирование структуры `domain.NotificationFeed`.
* **Ошибки:** `ErrValidationFailed`, `ErrInternalDB`.

---

### 2.3. Пометка уведомления как прочитанного (`MarkAsRead`)
* **Входные параметры:**
  * `userID` (`int64`) — текущий пользователь (гарантия изоляции данных).
  * `notificationID` (`int64`) — идентификатор целевого уведомления.
* **Пошаговый алгоритм:**
  1. Вызов обновления: `UPDATE notifications SET is_read = TRUE WHERE id = $1 AND user_id = $2`.
  2. Если ни одна строка не обновлена (уведомление не существует или принадлежит другому пользователю) — возврат `ErrNotificationNotFound`.
* **Ошибки:** `ErrValidationFailed`, `ErrNotificationNotFound`, `ErrInternalDB`.

---

### 2.4. Пометка всех уведомлений как прочитанных (`MarkAllAsRead`)
* **Входные параметры:**
  * `userID` (`int64`) — идентификатор пользователя.
* **Пошаговый алгоритм:**
  1. Вызов пакетного обновления: `UPDATE notifications SET is_read = TRUE WHERE user_id = $1 AND is_read = FALSE`.
  2. Успешный возврат `nil`.
* **Ошибки:** `ErrValidationFailed`, `ErrInternalDB`.
