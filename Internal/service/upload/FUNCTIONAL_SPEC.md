# 📋 Функциональная спецификация: Модуль загрузки файлов (`internal/service/upload`)

---

## 🎯 Бизнес-назначение модуля
Сервис предоставляет централизованный механизм безопасного приёма, валидации и хранения бинарных файлов для платформы: аватарок пользователей, обложек курсов, практических заданий и домашних работ студентов.

---

## 🛡 Безопасность и ограничения
- **Максимальный размер:** 25 МБ (`26,214,400` байт) для обычных файлов и 50 МБ (`52,428,800` байт) для слайдовых презентаций (`category = presentation`). Файлы большего размера отклоняются с ошибкой `400 Bad Request (FILE_TOO_LARGE)`.
- **Проверка сигнатуры (Magic Bytes):** Заголовок первых 512 байт анализируется через `http.DetectContentType`. Клиентскому заголовку `Content-Type` сервер не доверяет.
- **Разрешенные типы:**
  - Изображения: `image/jpeg`, `image/png`, `image/webp`, `image/gif`
  - Документы/архивы: `application/pdf`, `application/zip`, `application/x-zip-compressed`
  - Для категории `presentation`: строго разрешен только `application/pdf` с расширением `.pdf`.
- **Черный список расширений:** Строгий запрет на исполняемые файлы (`.exe`, `.sh`, `.php`, `.js`, `.bat`, `.cmd`, `.py`, `.bin`, `.msi`, `.dll`, `.com`, `.vbs`, `.ps1`, `.html`, `.htm`, `.jar`).
- **Безопасное именование:** Оригинальное имя файла не используется в файловой системе во избежание Path Traversal атак; файлу присваивается криптостойкий UUID v4 с оригинальным расширением.

## 📑 Паспорт функции: `UploadFile`

- **Сигнатура:**
  `UploadFile(ctx context.Context, file io.Reader, filename string, size int64, category string) (*domain.FileUploadResult, error)`

- **Входные параметры:**
  - `file` (`io.Reader`): бинарный поток данных файла.
  - `filename` (`string`): исходное имя файла, переданное клиентом (например, `report.pdf`).
  - `size` (`int64`): размер файла в байтах.
  - `category` (`string`): категория файла (`avatar`, `course_cover`, `homework`, `general`, `lesson_media`, `presentation`). Если не указана или невалидна, устанавливается `general`.

- **Пошаговый алгоритм выполнения:**
  1. Проверить, что `size > 0` (иначе ошибка `ErrEmptyFile`).
  2. Нормализовать категорию (`avatar`, `course_cover`, `homework`, `lesson_media`, `presentation` или fallback `general`).
  3. Определить лимит размера: 50 МБ для `presentation`, 25 МБ для остальных категорий. При превышении вернуть ошибку `ErrFileTooLarge`.
  4. Проверить расширение файла по черному списку опасных исполняемых файлов (иначе ошибка `ErrInvalidFileType`).
  5. Для категории `presentation` проверить, что расширение строго `.pdf`.
  6. Прочитать первые 512 байт для определения MIME-типа через сигнатуру (magic bytes).
  7. Проверить MIME-тип по белому списку допустимых типов (иначе ошибка `ErrInvalidFileType`).
  8. Для категории `presentation` проверить, что MIME-тип строго `application/pdf`.
  9. Сгенерировать UUID v4 для безопасного имени файла.
  10. Сформировать относительный путь: `{category}/{YYYY}/{MM}/{uuid}{ext}`.
  11. Объединить прочитанный буфер и остаток потока через `io.MultiReader` и записать в хранилище `storage.Save`.
  12. Залогировать успешную загрузку с метаданными.
  13. Вернуть объект `FileUploadResult` с публичным URL `/static/uploads/{category}/{YYYY}/{MM}/{uuid}{ext}`.

- **Выходные данные (`FileUploadResult`):**
  - `FileURL`: относительный публичный путь к файлу.
  - `FileName`: исходное имя файла.
  - `SizeBytes`: фактический размер файла.
  - `MimeType`: проверенный MIME-тип.

- **Возможные ошибки:**
  - `errorsAPP.ErrEmptyFile` (400) — пустой файл.
  - `errorsAPP.ErrFileTooLarge` (400) — размер больше 25 МБ (или больше 50 МБ для `presentation`).
  - `errorsAPP.ErrInvalidFileType` (400) — запрещенное расширение, неподдерживаемый MIME-тип или не-PDF для категории `presentation`.

## 📑 Паспорт функции: `UploadImagesBatch`

- **Сигнатура:**
  `UploadImagesBatch(ctx context.Context, files []domain.BatchFileItem, category string) ([]domain.BatchUploadResultItem, error)`

- **Бизнес-назначение:**
  Пакетная загрузка встроенных иллюстраций из импортируемых документов (Word `.docx`, презентаций) для оптимизации контента уроков и предотвращения раздувания размера JSON через Base64 Data URL.

- **Входные параметры:**
  - `files` (`[]domain.BatchFileItem`): массив элементов с потоком чтения, оригинальным именем и размером каждого файла.
  - `category` (`string`): категория медиафайлов (по умолчанию `lesson_media`).

- **Ограничения пакета:**
  - Максимум 50 изображений в одном пакете (`MaxBatchFileCount`).
  - Суммарный объем файлов пакета — не более 50 МБ (`MaxBatchTotalSize`).
  - Разрешенные форматы строго ограничены изображениями: `image/jpeg`, `image/png`, `image/webp`, `image/gif`.
  - Допустимые расширения: `.jpg`, `.jpeg`, `.png`, `.webp`, `.gif`.

- **Пошаговый алгоритм выполнения:**
  1. Проверить количество файлов: при `len == 0` вернуть `ErrEmptyFile`, при `len > 50` вернуть `ErrBatchTooManyFiles`.
  2. Проверить размер каждого файла (`> 0` и `<= 25 MB`) и суммарный размер пакета (`<= 50 MB`).
  3. Нормализовать категорию: если не входит в перечень разрешенных, выставлять `lesson_media`.
  4. Создать `errgroup.Group` с контекстом запроса и семафор с ограничением конкурентности (10 параллельных горутин).
  5. В параллельных горутинах для каждого файла:
     - Проверить расширение по белому списку графических форматов и черному списку опасных исполняемых файлов.
     - Прочитать первые 512 байт и выполнить проверку сигнатуры (magic bytes) через `http.DetectContentType`.
     - Сгенерировать криптографический UUID v4.
     - Сохранить файл в хранилище через `s.storage.Save` с сохранением путей `{category}/{YYYY}/{MM}/{uuid}{ext}`.
     - Записать результат в срез с сохранением исходного порядка файлов.
  6. Дождаться завершения горутин (`g.Wait()`). При ошибке любого файла прервать выполнение и вернуть ошибку.
  7. Залогировать успешную пакетную загрузку с указанием количества файлов и суммарного объема байт.
  8. Вернуть массив `[]domain.BatchUploadResultItem`.

- **Выходные данные:**
  - Массив элементов со структурой:
    - `OriginalName`: исходное имя файла (`image1.png`).
    - `FileURL`: постоянный публичный путь (`/static/uploads/lesson_media/2026/10/...png`).
    - `SizeBytes`: размер файла в байтах.
    - `MimeType`: распознанный MIME-тип.

- **Возможные ошибки:**
  - `errorsAPP.ErrEmptyFile` (400) — пустой массив файлов или файл нулевого размера.
  - `errorsAPP.ErrBatchTooManyFiles` (400) — более 50 файлов в одном пакете.
  - `errorsAPP.ErrFileTooLarge` (400) — суммарный объем превышает 50 МБ или один файл > 25 МБ.
  - `errorsAPP.ErrInvalidFileType` (400) — неподдерживаемое расширение или MIME-тип (не изображение).
