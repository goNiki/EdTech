## 🔬 Паспорта функций

### ⚡ Функция: `GetCourseAnalytics(ctx, teacherID, courseID)`

* **Файл и строки:** [`getCourseAnalytics.go#L10-L23`](file:///c:/Users/gogol/OneDrive/Desktop/EdTech/internal/service/analytics/getCourseAnalytics.go#L10-L23)
* **Бизнес-назначение:** Предоставление ключевых метрик успеваемости потока для панели преподавателя.
* **Связанная фича:** *Сводная статистика курса*

#### 📥 Входные параметры
| Параметр | Тип | Обязателен | Бизнес-смысл и ограничения |
|---|---|:---:|---|
| `teacherID` | `int64` | Да | Идентификатор запрашивающего преподавателя |
| `courseID` | `int64` | Да | Идентификатор курса |

#### 🔄 Пошаговый алгоритм работы
1. **Шаг 1 (Авторизация):** Вызывает внутреннюю проверку `checkTeacherAccess(teacherID, courseID)` ➔ через `accessService.CanEditCourse` проверяет права преподавателя (403 при отказе).
2. **Шаг 2 (Сбор агрегатов):** Запрашивает через `analyticsRepo.GetCourseAnalyticsSummary` расчет показателей:
   - `TotalStudents` — число учащихся на курсе.
   - `AvgProgressPercent` — средний % прохождения материалов потоком.
   - `AvgScore` — средний балл по курсу.
   - `PendingHomeworksCount` — общее число работ в очереди на проверку.

* **Файл и строки:** [`getStudentDrilldown.go#L10-L23`](file:///c:/Users/gogol/OneDrive/Desktop/EdTech/internal/service/analytics/getStudentDrilldown.go#L10-L23)
* **Бизнес-назначение:** Глубокая инспекция успеваемости конкретного учащегося преподавателем.
* **Связанная фича:** *Детальное досье студента (Drilldown)*

#### 📥 Входные параметры
| Параметр | Тип | Обязателен | Бизнес-смысл и ограничения |
|---|---|:---:|---|
| `teacherID` | `int64` | Да | Идентификатор преподавателя |
| `courseID` | `int64` | Да | Идентификатор курса |
| `studentID` | `int64` | Да | Идентификатор инспектируемого студента |

#### 🔄 Пошаговый алгоритм работы
1. **Шаг 1 (Авторизация):** Проверяет доступ преподавателя к курсу (`checkTeacherAccess`).
2. **Шаг 2 (Сбор досье):** Запрашивает через репозиторий агрегированный отчет:
   - Профиль студента (`domain.User`).
   - Итоговый прогресс (`OverallProgress`) и средний балл (`AvgScore`).
   - Лог по всем урокам (`LessonLogs`): тип, статус (`not_started`, `in_progress`, `completed`), оценка, время завершения, последний доступ.
   - Историю тестов (`TestAttempts`): номер попытки, статус прохождения, детальный разбор каждого вопроса с выбранным вариантом, правильным ответом, баллами и фидбеком преподавателя.

### ⚡ Функция: `ListPendingHomeworks(ctx, teacherID, courseID, page, pageSize)`

* **Файл и строки:** [`listPendingHomeworks.go#L10-L31`](file:///c:/Users/gogol/OneDrive/Desktop/EdTech/internal/service/analytics/listPendingHomeworks.go#L10-L31)
* **Бизнес-назначение:** Постраничный просмотр очереди домашних заданий и эссе, ожидающих проверки.
* **Связанная фича:** *Единая очередь непроверенных ДЗ*

#### 📥 Входные параметры
| Параметр | Тип | Обязателен | Бизнес-смысл и ограничения |
|---|---|:---:|---|
| `teacherID` | `int64` | Да | Идентификатор преподавателя |
| `courseID` | `int64` | Да | Идентификатор курса |
| `page` | `int64` | Нет | Номер страницы (по умолчанию 1) |
| `pageSize` | `int64` | Нет | Количество записей на страницу (от 1 до 100, по умолчанию 20) |

#### 🔄 Пошаговый алгоритм работы
1. **Шаг 1 (Авторизация):** Проверяет доступ преподавателя (`checkTeacherAccess`).
2. **Шаг 2 (Нормализация пагинации):** `page < 1 => 1`, `pageSize < 1 || pageSize > 100 => 20`. Расчет смещения `offset = (page - 1) * pageSize`.
3. **Шаг 3 (Выборка очереди):** Запрашивает через SQL срез работ, где `is_correct IS NULL` и `needs_grading = true`. Возвращает карточки работ со ссылками на вложенные файлы и критериями оценивания (рубриками), а также общее количество работ `total`.

### ⚡ Функция: `ListTeacherPendingHomeworks(ctx, teacherID, courseID, page, pageSize)`

* **Файл и строки:** [`list_teacher_pending.go`](file:///c:/Users/gogol/OneDrive/Desktop/EdTech/internal/service/analytics/list_teacher_pending.go)
* **Бизнес-назначение:** Глобальная агрегация всех непроверенных работ преподавателя по всем его курсам, устраняющая проблему ложного статуса «все проверено» при выборе курса вслепую.
* **Связанная фича:** *Кросс-курсовая очередь проверки*

#### 📥 Входные параметры
| Параметр | Тип | Обязателен | Бизнес-смысл и ограничения |
|---|---|:---:|---|
| `teacherID` | `int64` | Да | Идентификатор запрашивающего преподавателя/автора |
| `courseID` | `int64` | Нет | Идентификатор курса для фильтрации (0 — все курсы автора) |
| `page` | `int64` | Нет | Номер страницы (по умолчанию 1) |
| `pageSize` | `int64` | Нет | Количество записей на страницу (от 1 до 100, по умолчанию 20) |

#### 🔄 Пошаговый алгоритм работы
1. **Шаг 1 (Проверка доступа):** Если передан `courseID > 0`, проверяется принадлежность курса преподавателю через `checkTeacherAccess` (403 при попытке запросить чужой курс).
2. **Шаг 2 (Нормализация пагинации):** `page < 1 => 1`, `pageSize < 1 || pageSize > 100 => 20`.
3. **Шаг 3 (SQL-выборка):** Выполняет запрос к БД, возвращая:
   - Сводку `courses_summary` по каждому курсу автора с количеством ожидающих проверки работ (включая курсы с 0 не проверенных работ).
   - Общее количество `total` работ, ожидающих проверки.
   - Пагинированный список `items` с деталями студента, курса, урока, вопроса и прикрепленных файлов.
4. **Шаг 4 (Защита от nil):** Гарантирует возврат не-nil слайсов `[]` при отсутствии данных.
