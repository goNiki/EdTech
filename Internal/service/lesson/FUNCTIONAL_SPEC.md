### ⚡ Функция: `UpdateLesson(ctx, userID, lesson)`

* **Файл и строки:** [`updateLesson.go#L12-L79`](file:///c:/Users/gogol/OneDrive/Desktop/EdTech/internal/service/lesson/updateLesson.go#L12-L79)
* **Бизнес-назначение:** Изменение параметров урока и сохранение структуры контента Puck Editor (включая крупные наборы импортированных интерактивных тестов).
* **Связанная фича:** *Редактирование урока*

#### 📥 Входные параметры
| Параметр | Тип | Обязателен | Бизнес-смысл и ограничения |
|---|---|:---:|---|
| `userID` | `int64` | Да | Идентификатор преподавателя/автора, инициирующего обновление |
| `lesson.ID` | `int64` | Да | Идентификатор обновляемого урока |
| `lesson.Title` | `string` | Нет | Новое название урока (1–255 символов) |
| `lesson.Description` | `string` | Нет | Новое описание урока |
| `lesson.Content` | `string` | Нет | Puck JSON контент урока. Должен быть валидным JSON (до 5 МБ) со схемой блоков и уникальными `props.id` |
| `lesson.Type` | `string` | Нет | Тип урока (`lecture`, `exercise`, `practice`, `quiz`, `assignment`, `homework`) |

#### 🔄 Пошаговый алгоритм работы
1. **Шаг 1 (Проверка существования):** Ищет существующий урок в `lessonrepo.GetLessonByID`. При отсутствии возвращает `ErrNotFoundLesson`.
2. **Шаг 2 (RBAC авторизация):** Проверяет права пользователя на редактирование курса (`accessService.CanEditCourse`). Если доступ запрещен — возвращает `ErrForbidden`.
3. **Шаг 3 (Слияние полей):** Выполняет частичное обновление (partial merge): незаполненные поля сохраняют текущие значения из БД.
4. **Шаг 4 (Валидация домена и Puck JSON):** Вызывает `lesson.Validate()`:
   - Проверяет обязательные метаданные (`Title`, `Description`, `CourseID`).
   - Если передан `Content`, вызывает `ValidateLessonContent(content)`:
     - Проверяет валидность JSON-синтаксиса.
     - Проверяет структуру списка блоков (корневой объект с полем `content` или массив).
     - Проверяет наличие обязательного поля `type` у каждого блока.
     - Для всех интерактивных квиз-блоков гарантирует наличие идентификатора `props.id`.
     - Защищает от дублирования идентификаторов блоков внутри одного урока (`seenIDs`).
5. **Шаг 5 (Сохранение в БД):** Вызывает `lessonrepo.UpdateLesson(ctx, lesson)` для сохранения текстового JSON в PostgreSQL.

#### ⚠️ Побочные эффекты (Side Effects)
* **База данных:** Мутирует строку урока в таблице `lessons`, обновляя `updated_at = NOW()`.

#### 📤 Результат и ошибки
* **Успешный результат:** `nil` (код 200 OK).
* **Возможные ошибки:**
  * `ErrNotFoundLesson` (404) — урок не найден.
  * `ErrForbidden` (403) — нет прав на редактирование курса.
  * `ErrLessonValidation` (400) — некорректный Puck JSON, дубликаты ID блоков или отсутствующий `type`.
  * `ErrFileTooLarge` (400) — превышение максимального лимита размера тела запроса (5 МБ).

### ⚡ Функция: `GetLessonNavigationContext(ctx, userID, lessonID)`

* **Файл и строки:** [`getLessonNavigation.go#L11-L157`](file:///c:/Users/gogol/OneDrive/Desktop/EdTech/internal/service/lesson/getLessonNavigation.go#L11-L157)
* **Бизнес-назначение:** Предоставление данных для бесшовного перемещения учащегося по урокам курса (кнопки «← Предыдущий урок» / «Следующий урок →») и компактного выпадающего оглавления курса (Syllabus Sheet) с прогрессом и баллами студента без выполнения множества параллельных тяжелых запросов.
* **Связанная фича:** *Контекст навигации и силлабус*

#### 📥 Входные параметры
| Параметр | Тип | Обязателен | Бизнес-смысл и ограничения |
|---|---|:---:|---|
| `userID` | `int64` | Да | Идентификатор студента/пользователя (для проверки доступа и загрузки прогресса) |
| `lessonID` | `int64` | Да | Идентификатор текущего открытого урока |

#### 🔄 Пошаговый алгоритм работы
1. **Шаг 1 (Получение текущего урока):** Ищет урок по `lessonID` в `lessonrepo.GetLessonByID`. Если не найден ➔ ошибка `ErrLessonNotFound`.
2. **Шаг 2 (Получение курса):** Извлекает привязанный курс по `lesson.CourseID` через `courserepo.GetCourseByID`.
3. **Шаг 3 (RBAC валидация доступа к курсу):** Проверяет доступ через `accessService.CanViewCourse(ctx, course, userID)`. Если доступ закрыт (чужой/незачисленный студент на закрытом курсе) ➔ возвращает `ErrForbidden` (HTTP 403 Forbidden).
4. **Шаг 4 (Получение силлабуса курса):**
   - Извлекает секции курса через `sectionrepo.ListSectionsByCourseID` (`ORDER BY position ASC`).
   - Извлекает все уроки курса через `lessonrepo.GetLessonsByCourseID`.
5. **Шаг 5 (Сбор успеваемости студента):**
   - Запрашивает прогресс пользователя по курсу через `progressrepo.GetAllLessonProgressByCourse(ctx, userID, course.Id)`.
   - Индексирует прогресс в карте `map[lessonID]*LessonProgress` для мгновенного сопоставления статуса (`is_completed`) и баллов (`score`).
6. **Шаг 6 (Построение учебного порядка и силлабуса):**
   - Группирует уроки по секциям.
   - Внутри каждой секции сортирует уроки по `position ASC`.
   - Формирует итоговую иерархическую структуру `Syllabus` с отметками прохождения уроков (`is_completed: true` при `status == 'completed'`) и баллами.
   - Формирует единый сквозной плоский список уроков курса `flatLessons` в порядке следования секций и уроков.
7. **Шаг 7 (Определение соседей prev/next):**
   - Находит индекс текущего урока `currIdx` в `flatLessons`.
   - Если `currIdx > 0` ➔ `prev_lesson = flatLessons[currIdx - 1]`, иначе `prev_lesson = null`.
   - Если `currIdx < len - 1` ➔ `next_lesson = flatLessons[currIdx + 1]`, иначе `next_lesson = null`.
8. **Шаг 8:** Возвращает структуру `LessonNavigationContext` с текущим уроком, курсом, соседними уроками и деревом силлабуса.

#### ⚠️ Побочные эффекты (Side Effects)
* Нет (чистая операция чтения).

#### 📤 Результат и ошибки
* **Успешный результат:** `*domain.LessonNavigationContext` (код 200 OK).
* **Возможные ошибки:**
  * `ErrLessonNotFound` (404) — урок не найден.
  * `ErrCourseNotFound` (404) — курс не найден.
  * `ErrForbidden` (403) — нет доступа к просмотру курса.
  * `ErrInternalDB` (500) — ошибка при обращении к БД.
